# 交互原型与构建说明

三个交付文件都在项目根目录，直接用浏览器打开即可，无需安装依赖或运行服务器：

| 文件 | 内容 |
|---|---|
| `prototype.html` | 管理后台原型 · 6 个模块 / 17 个视图 |
| `mobile.html` | 点检员移动端 · 3 个标签页 |
| `product-structure.html` | 产品结构说明页 · 9 个模块 / 114 条需求，可打印 |

三者顶部互链，**分享时必须放在同一文件夹并保留文件名**。

## 浏览方法

**管理后台**

- 左侧切换看板中心、舱室 / 部位管理、标签管理、点检引擎、环境监测、系统管理。
- 看板中心第一页顶部有三档角色切换（中高层 / 专业主管 / 专业工人），可逐层钻取：分段 → 舱室 → 设备；第二页是系统监控看板与统一告警中心。
- 右侧显示当前页面对应的 v0.4 需求原文，并标注「可点击演示 / 查看简化演示 / 原型未实现」。演示入口只做跳转与高亮，不会自动保存、导出、下发或改变业务数据。
- 左下角「完整产品文档」内嵌整份 v0.4 文档；「查看演示路线」给出推荐操作顺序。

**移动端**

- 三个标签页：今日点检 / 离线队列 / 需求对照。
- 「碰一碰」在本原型中是手动选标签模拟，**不构成 NFC 可用的证据**。
- 完成页把一次点检拆成三段分别显示：手机本地已保存 / 边缘服务已接收 / 标签已刷新。

## 本地数据

- 业务数据键 `ship-tag-prototype-v1`，结构版本 `4`；管理后台与移动端**共用**（同源打开时是同一份）。
- 移动端离线队列键 `ship-tag-mobile-v1`，**单独存**——离线移动端与离线网关本就是两个互不相关的缓存域。
- 版本不符会自动重新播种，此前的演示修改会被清空。管理后台右上角可手动「重置演示」。
- 不同浏览器之间不共享；发送 HTML 文件不会携带当前浏览器里的修改。
- 原型带演示基准时间 `2026-09-15 10:00:00`，点检状态相对它推算，任何日期打开都是同一套示例状态。

## 原型范围

示例数据、在线状态与硬件反馈全部模拟，不连接网关或现场标签。

未实现：Excel 导入、完整拖拽模板编辑器、图片／二维码／条形码素材编辑、后台定时调度、真实权限、真实 NFC 唤起、真实拍照上传、工单状态机、MES/EAM 对接。「变屏变灯」是界面模拟。

**不能据原型判断厂商能力或生产可用性。**

## 源码与构建

| 文件 | 作用 |
|---|---|
| `docparse.py` | v0.4 文档解析：需求提取与 Markdown 渲染，被下面三个构建脚本共用 |
| `build.py` | 打包管理后台原型 + 构建期 id 校验 |
| `build_structure.py` | 重建结构说明页的模块地图与功能清单 |
| `build_mobile.py` | 打包移动端原型 + 移动端需求实现状态校验 |
| `app.js` / `styles.css` / `shell.html` | 管理后台源码 |
| `../mobile/app.js` / `styles.css` / `shell.html` | 移动端源码 |

在项目根目录运行：

```bash
python3 prototype/build.py && python3 prototype/build_structure.py && python3 prototype/build_mobile.py
```

构建仅使用 Python 标准库。**不要直接编辑生成后的三个 HTML**，下次构建会覆盖。

### 需求映射不再依赖表格顺序

`coverage` / `requirementDemos` 按 **id 键**引用需求（模块 slug / 功能名），不是零起始索引。因此：

- 在文档表格中间插入或删除行是**安全的**；
- 改功能名会让构建**直接失败**并列出失配的 id，不会静默产出错页面。

结构说明页的模块地图与功能清单夹在 `<!--MAP-->` / `<!--SPECS-->` 标记之间，由脚本生成，**不要手工编辑这两段**；其余段落仍为手工维护。
