层级示例 · 设备资产与标签不占目录层级。
四级目录：Hull No. → 分段 → 舱室 → 部位。部位层可跳过，设备可直接挂在舱室下；各级显示名称可配置。

A
一套数据，两个管理入口

舱室 / 部位管理从分段、舱室和部位查看资产；标签管理面向全船维护。同一资产与标签数据保持一致。

B
分组可以跨舱室

按设备类型、责任班组或维护用途组织标签，集中应用模板、下发内容。

C
在线与更新结果分别判断

标签在线不代表屏幕已更新。下发任务需要跟踪到成功确认、失败或结果待确认。

03 / WORKFLOW

从建档到点检闭环

一期核心业务链路

  1. 01建立四级目录分段 → 舱室 → 部位
  2. 02录入设备台账含保养周期与检查项
  3. 03扫码绑定标签自动触发首次刷屏
  4. 04引擎推算截止按保养周期自动计算
  5. 05临期 / 逾期预警黄色慢闪 → 红色高频闪
  6. 06现场碰一碰点检离线填报、拍照存证
  7. 07变屏变灯闭环截止日后移、绿灯 3 秒
  8. 08三层看板汇总宏观 → 管理 → 执行

↳ 环境超限会缩短保养周期并重算截止时间；点检完成后标签内容变化，需重新下发才会刷屏——标签在线不等于屏幕已更新。

以下为待确认或已知风险

  • 标签 NFC 是单点依赖：候选机规格中 NFC 仅标为「可选」，未给芯片型号与防克隆方案。移动端防假检与二期上电确认都建立在这一条上。
  • 环境适应性冲突：候选机工作范围 0–40°C、45–70% RH 且无 IP 等级；需要监测高湿告警的舱室，标签自身未必能工作。

  • Docker 私有化、网关 30 天缓存、REST／MQTT 北向接口均无厂商书面承诺。
