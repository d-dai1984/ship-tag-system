# 船舶资产电子标签管理系统

本项目面向船舶资产的电子标签分类、内容维护、下发更新和状态查看。当前已有产品需求大纲、可离线分享的结构说明页及可对照需求浏览的交互原型。早期“智能墨水屏设备点检标签系统”的技术资料与硬件评估作为后续背景保留。

## 新电脑 / 新任务快速开始

按以下顺序阅读：

1. [`PROJECT_MEMORY.md`](PROJECT_MEMORY.md)：长期稳定的项目背景、需求基线、已知边界和决策。
2. [`HANDOFF.md`](HANDOFF.md)：当前阶段、最近进展、阻塞项和下一步。
3. [`船舶资产智能点检标签管理系统-产品结构与功能范围-v0.4.md`](船舶资产智能点检标签管理系统-产品结构与功能范围-v0.4.md)：**当前产品讨论稿**，原型嵌入的就是它。
4. [`船舶资产电子标签管理系统-产品需求大纲-v0.1.md`](船舶资产电子标签管理系统-产品需求大纲-v0.1.md)：历史版本，仅目录层级条款做过修订。
5. [`prototype/README.md`](prototype/README.md)：交互原型的使用、范围与重建方法。
5. `docs/技术要求.pdf`：早期点检和部署技术背景，不自动扩大当前原型范围。
6. `docs/STag29AQ中文规格书.pdf` 与 `docs/云里物里公司和产品介绍.pdf`：分别提供型号规格及厂商生态背景，不能替代现场验证。

## 当前状态

- 可点击后台原型：[`prototype.html`](prototype.html)，六个模块、17 个视图，含三层角色看板、点检引擎、环境监测与系统监控看板；源码位于 `prototype/`。
- 点检员移动端：[`mobile.html`](mobile.html)，碰一碰、离线作业、防呆表单与三段闭环反馈；源码位于 `mobile/`。
- 沟通展示页：[`product-structure.html`](product-structure.html)，单文件离线打开，支持模块跳转、功能展开与打印。
- 三个 HTML 顶部互链，分享时请放在同一文件夹并保留文件名。
- 最新产品讨论稿：[`产品结构与功能范围 v0.4`](船舶资产智能点检标签管理系统-产品结构与功能范围-v0.4.md)，覆盖舱室/部位管理、标签管理、点检引擎、看板中心、环境监测、移动端及二期设备调试管理。
- 原型与结构说明页均已对齐 v0.4：114 条需求，原型覆盖 77 条，未实现的明确标注。
- 三个 HTML 的需求内容都由 `prototype/docparse.py` 从 v0.4 文档生成，同源同 id。改完文档依次运行：

```bash
python3 prototype/build.py && python3 prototype/build_structure.py && python3 prototype/build_mobile.py
```
- 阶段：产品范围梳理与交互原型沟通；生产开发、硬件接入和采购验证尚未完成。
- 当前候选硬件：云里物里 `STag29AQ` 2.9 英寸四色按键电子标签。
- 总体判断：可作为概念验证候选，但现有资料不足以证明其满足船厂工业环境和完整业务闭环；采购前必须完成技术澄清与样机验证。

## 项目文档维护约定

### GitHub 发布范围

仓库收录产品需求大纲、两个单文件 HTML、`prototype/` 源码及项目记忆和交接文档。`docs/` 下的三份原始参考 PDF 保留在本地，不包含在本次上传中；从 GitHub 下载后仍可直接打开两个 HTML，或运行 `python3 prototype/build.py` 重建交互原型。

### 维护规则

- 稳定事实、正式决策、需求边界写入 `PROJECT_MEMORY.md`。
- 当期进展、负责人、阻塞、下一动作写入 `HANDOFF.md`。
- 原始资料只放在 `docs/`，不直接改写；替换文件时记录版本、日期和 SHA-256。
- 厂商宣传材料中的“支持”“可选”“可定制”均视为待确认，不自动等于交付承诺。
- 任何重要结论都要注明来源；推断和已验证事实必须分开。
